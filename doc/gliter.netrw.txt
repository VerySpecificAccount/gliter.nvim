1. gliter.netrw                                    *gliter.netrw-gliter.netrw*

Enhances Neovim’s built-in netrw (0.12+) with entry marks that are shared
across every netrw buffer, window and tab page, one-key commands that act on
them, nine numbered bookmarks that survive restarts, marking by regexp with a
live highlight, and in-place editing of the listing itself: add, remove and
rename files and directories by editing the buffer text. It does not replace
netrw.


  **Neovim 0.13+ note.** Neovim is growing a new built-in directory browser
  (`nvim.dir`, filetype `directory`) that replaces netrw when it is finished;
  this module rides on classic netrw and stays out of the way when `nvim.dir` has
  taken the buffer. To keep using netrw — and this module with it — set `let
  g:loaded_nvim_dir_plugin = 1` (init.vim) or `vim.g.loaded_nvim_dir_plugin = 1`
  (init.lua, early) before startup.

STOLEN FROM EMACS                *gliter.netrw-gliter.netrw-stolen-from-emacs*

The keys below are stolen from Emacs. The marks are dired’s marks, the
one-key commands are dired’s commands, editing the listing in place is wdired
— also an Emacs thing — and the bookmarks are Emacs registers with the
two-key prefix amputated: `C-x r SPC` and `C-x r j` there, one `C-<digit>`
here. dired has done it this way since 1986, five years before Vim existed;
wdired since the early 2000s, twenty years before oil.nvim
<https://github.com/stevearc/oil.nvim> (2022) built a whole plugin around the
same trick. This was inevitable: every Neovim plugin ends up at Emacs
eventually, and the only real choice is whether it takes the direct flight.
gliter.netrw skips the usual decade of insisting it is not an Emacs clone and
just ships the Emacs part. If you have used dired, your hands already know
everything on this page.


INSTALL                                    *gliter.netrw-gliter.netrw-install*

`gliter.netrw` is a module of gliter (one repository, one runtime path), and
modules are opt-in — gliter’s `setup()` only sets up the modules you name
in it:

>
    { 'you/gliter', opts = { netrw = { star_kind = 'copy' } } }
<

or, without a plugin manager, set the module up straight from your init.lua:

>
    require('gliter.netrw').setup { star_kind = 'copy' }
<

**netrw and Neovim 0.13.** 0.13 stops loading netrw by default — `:edit
some/directory` opens the new built-in `dir` plugin (`dir.lua`, new in 0.13)
instead — and netrw became a legacy plugin that `:packadd netrw` turns back
on. On 0.13, put `vim.cmd('packadd netrw')` in your init.lua before gliter.
Below 0.13 netrw still loads by itself (a shim in
`runtime/plugin/netrwPlugin.vim` does the `:packadd` at startup), so users of <
0.13 don’t need the line — but might want `:packadd netrw` in their
init.lua anyway: it is harmless there, and it is already in place for the day
0.13 arrives.

Every key on this page is changeable — or switchable off with `false` —
through the `keys` table of `setup()`; see |gliter.netrw-gliter.netrw-keys|.
The `%` and `*` sequences are built from the same table, so remapping a mark
key remaps its sequences with it.


MARKS                                        *gliter.netrw-gliter.netrw-marks*

  -----------------------------------------------------------------------
  Key                         Action
  --------------------------- -------------------------------------------
  y                           toggle a copy mark on the entry under the
                              cursor (Visual: each selected line)

  m                           toggle a move mark on the entry under the
                              cursor (Visual: each selected line)

  d                           toggle a delete mark on the entry under the
                              cursor (Visual: each selected line)

  z                           toggle an archive mark on the entry under
                              the cursor (Visual: each selected line)

  Y M gD Z                    mark every entry for copy / move / delete /
                              archive (press again to unmark all)

  p                           apply the marks (see below)

  <Esc>                       clear all marks
  -----------------------------------------------------------------------
Marks are single-key actions: `y`, `m`, `d` and `z` act at once, with no second
key to type. Because of that, keys that start with a mark letter cannot be
reached in netrw buffers: netrw’s `m`-prefixed keys (`mf`, `mt`, …), and
Vim’s `ZZ`/`ZQ` under the default `Z`. Marks are shared across every netrw
window and tab page — until a window switches to another directory: the marks
are forgotten then (they belong to the listing you set them on; a refresh, sort
or style change of the same directory keeps them). Marking an entry again with
the same key unmarks it; marking it with another key changes its kind. After a
single-entry toggle the cursor moves down one line, like fff.nvim. Marked lines
are highlighted — copy, move, delete, shell, archive and run use different
colors — and show a `[copy]`, `[move]`, `[delete]`, `[shell]` or `[archive]`
tag. Marks for entries that were applied successfully are cleared.


APPLYING THE MARKS WITH P *gliter.netrw-gliter.netrw-applying-the-marks-with-p*

- **copy / move marks** are pasted into the current directory (in tree style:
    into the directory under the cursor). When a pasted entry already exists you
    are asked what to do, unless `conflict` says otherwise.
- **delete marks** are confirmed first — a `y`/`n` prompt listing what would go
    — and deleted when you answer `y`. Answering `n` aborts the whole paste and
    keeps the marks.
- **archive marks** are confirmed with a prompt, in two halves: entries that are
    themselves netrw-browsable archives (`.tar`, `.tar.gz`, `.tgz`, `.zip`, …)
    are **extracted** into a directory you type — Enter keeps the directory netrw
    is listing here, and the directory is created if it does not exist; every
    other entry is **packed** into a new archive whose name you type, and the
    extension of that name picks the format: `.tar`, `.tar.gz`/`.tgz`,
    `.tar.bz2`/`.tbz2`, `.tar.xz`/`.txz`, `.tar.zst`/`.tzst`, `.zip`. A mix of
    both does both, one prompt each (extraction first). Extraction overwrites
    existing files (tar’s default; `unzip -o`); packing refuses to overwrite an
    existing archive. Entries that were extracted or packed successfully lose
    their mark.
- **shell and run marks** are left alone: `p` does not run shell commands —
    `!` and `x` do. With nothing but shell/run marks marked, `p` says so and
    does nothing.


COMMANDS                                  *gliter.netrw-gliter.netrw-commands*

Each command acts on the marked entries of its kind, or on the entry under the
cursor when nothing of that kind is marked.

  -----------------------------------------------------------------------
  Key                         Action
  --------------------------- -------------------------------------------
  C                           copy copy-marked entries to a directory you
                              type (Tab completes)

  R                           rename/move move-marked entries to a typed
                              directory; a single entry can be given a
                              new path instead

  D                           delete delete-marked entries now, after
                              confirmation

  X                           chmod: toggle the executable bit on every
                              marked entry (any kind), or the one under
                              the cursor, or — from Visual mode — each
                              entry of the selection; files only,
                              directories are skipped

  S                           symlink marked entries into a typed
                              directory

  !                           run a shell command once on the !-marked
                              entries; with none of those, on any marked
                              entries, else on the entry under the
                              cursor. * in the command stands for the
                              files, otherwise they are appended

  x                           run the command one entry at a time: the
                              x-marked entries, else the same selection
                              as ! (its previous command is the default),
                              but each entry runs alone in a terminal,
                              the next one only when the previous command
                              exits. * stands for the entry being run;
                              close the terminal to stop the queue

  +                           create a file, or a directory when the name
                              ends in / (parents included)

  <C-g>                       cd: make the directory listed here the
                              current working directory (a global :cd;
                              netrw’s own c is a window-local :lcd)
  -----------------------------------------------------------------------
Inside netrw buffers these take over netrw’s own bindings for the same
letters (`C`, `R`, `D`, `S`, `x`, and `%` — removed so the `%<mark>`
sequences can exist, see `native_unmap`); netrw’s own `p` (preview) moves to
`preview` when `paste` is `p`.

There is no single-key shell mark (`!` itself runs the command). To mark
entries for `!`, use `%!` with a pattern, or the `*` family with `!` as the
kind letter (for instance `*!*` marks every executable for shell); for `x`, the
same with `x` — `%x` and `*x.`. Shell marks show as `[shell]` and are only
consumed by `!`; run marks show as `[run]` and are what `x` prefers. `p`
ignores both.


MARKING MANY ENTRIES AT ONCE *gliter.netrw-gliter.netrw-marking-many-entries-at-once*

  -----------------------------------------------------------------------
  Key                         Action
  --------------------------- -------------------------------------------
  %y %m %d %z %! %x           mark by regexp (copy / move / delete /
                              archive / shell / one-at-a-time run),
                              matched against the name as the listing
                              shows it — with the matches highlighted
                              live while you type

  *. */ *@ **                 mark by extension / directories / symlinks
                              / executables, with the default kind
                              (initially star_kind)

  *y. *y/ *y@ *y*             same families, but as copy — and copy
                              becomes the default kind

  *m/ *d@ *z* *!* *x. …       the same for move / delete / archive /
                              shell / run: *<kind><family> picks the kind
                              for that press and makes it the default
  -----------------------------------------------------------------------
The `*` family marks many entries at once: `*.` asks for an extension, `*/`
takes every directory, `*@` every symlink, `**` every executable. A mark key
between the `*` and the family does it in one sequence and re-binds the
default: `*y.` marks everything with that extension for copy (and copy is what
plain `*.` does from then on), `*m/` marks every directory for move, `*d@`
every symlink for delete, `*z*` every executable for archive. The default is
`star_kind` until one of these changes it.

The `%<mark>` regexp is a Vim regexp compiled the way a `/` search in the
listing would compile it, and it is matched against the text the listing
actually shows — `dir/` with its trailing slash, `link@`, `file*` — so a
pattern that finds something with a search finds it here too: `.\+\/` marks
exactly the directories, and nothing else. While you type, the matches are
highlighted live (in Search colors) and the prompt counts them, at the right
end of the line; Enter applies the mark, Esc leaves everything alone. The
prompt itself is the command line `input()` gives — gliter.cmd
<gliter.cmd.md> lays its readline keys and the ghost of the answers before on
it when it is set up, `Up`/`Down` walk the `@` history — Enter applies and
Esc cancels.

The letter after `%` and between `*` and the family is the mark key itself, not
a fixed letter: if you remap `yank` to `c`, the sequences become `%c` and
`*c.`, and `z` stays `%z` / `*z.`.


BOOKMARKS                                *gliter.netrw-gliter.netrw-bookmarks*

  -----------------------------------------------------------------------
  Key                         Action
  --------------------------- -------------------------------------------
  <C-1> .. <C-9>              jump to bookmark 1..9; an unset slot is
                              pointed at this directory first

  <C-b>1 .. <C-b>9            point bookmark 1..9 at this directory
                              (overwrites)

  <C-b>0                      clear all nine bookmarks

  <C-b>l                      list the bookmarks
  -----------------------------------------------------------------------
Nine numbered directories, one key each. "This directory" is the one the
listing acts on — the directory under the cursor in tree style, the listed
directory otherwise — the same target `+` and `p` use. The slots survive
restarts: they live in `stdpath('data')/gliter/netrw-bookmarks.json`.
`:GliterNetrwBookmarks` lists them from anywhere. Jumping to a bookmark whose
directory has been removed says so and leaves the slot alone.

A slot jumps on the second press, never the first: pressing `<C-3>` with slot 3
empty points it here, so a fresh slot is planted exactly where you are standing
— and pressing it again right away stays there (a bookmark pointing at the
directory you are in is a no-op). `<C-b>3` is the explicit form — it
re-points a slot that is already set. The jump is a plain `:edit <dir>` — the
canonical way to open a directory, reusing whatever buffer already carries its
name — and gliter attaches its keys and decorations to the buffer it lands
on, so it is a gliter.netrw buffer like any other: same keys, same marks, same
decoration.


EDITING THE LISTING IN PLACE (E) *gliter.netrw-gliter.netrw-editing-the-listing-in-place-(e)*

`E` turns the listing buffer itself into an ordinary editable buffer (no popup,
no new window):

- Add a line to create a file; end it with `/` to create a directory. Nested
    paths (`sub/dir/file.txt`) create their parent directories.
- Delete a line (or clear its text) to delete that file or directory.
- Edit a name in place to rename it.
- Any normal Vim editing works: `:%s`, `<C-v>` block edits, `g<C-a>`, replaying
    macros with `@`… (recording a new macro is not possible: the cancel key —
    `q` by default — is taken by edit mode, see below).
- `:w` applies the changes to disk (asks to confirm first unless
    `edit.confirm = false`). Confirmations are answered with Enter (yes) or
    Backspace (no).
- `q` cancels: it leaves edit mode and discards the edits, asking first when
    there are unsaved changes. Pressing `E` again does the same.

Inside edit mode `p` adds the copy- and move-marked entries as new lines below
the cursor; they are copied or moved when the listing is saved with `:w`. A
copy whose name is already taken becomes `file_copy`; pasting the same entry
again takes the next free name — `file_copy_2`, `file_copy_3`, … — so a
second `y` + `p` is a second copy. Pasting consumes the marks — the sources
lose their `[copy]`/`[move]` tag and the new lines carry `[copied]`/`[moved]`
instead — and directories keep their trailing `/` on the pasted line, so the
pending entry reads as the directory it is. Pressing the mark key on a pending
line cancels it (the line is removed; re-mark to paste it somewhere else). `y`
also marks the entry on the cursor line while editing, `Y` marks every entry,
and `<Esc>` clears the marks. A confirmed `:w` clears _all_ marks, not just the
ones it executed — the listing on disk is the truth now. The other mark keys
keep Vim’s meaning while editing — `d` stays delete, so `dd` is how a line
is removed.

One directory per edit session. Tree-style listings switch to thin style while
editing; the banner is hidden while editing and restored afterwards. netrw’s
own auto-refresh — which fires on `BufEnter` and on `FocusGained` (switching
the terminal window away and back) and would rewrite the listing mid-edit —
is suspended for the duration of a session and restored when it ends, so the
edits (and the marks that track them) survive focus changes, window switches
and `:!` shell commands. The suspension deletes netrw’s `AuNetrwEvent`
autocommand _group_ (not the autocmds one by one — those carry no API id, and
deleting them individually silently fails, which is how a focus change used to
re-render the listing and make every entry read `[new]`).

And if a refresh slips past the suspension anyway (another plugin, a future
netrw): the edit detects it. Entries whose lines are still there, only without
their tracking mark, are _not_ read as delete-and-recreate — the pairs
cancel, deletions that cannot be verified are skipped with a notice, and the
session re-attaches its tracking and carries on. A refresh can at worst cancel
an edit; it can never empty the files.

While editing, hints show next to lines: `[copy]`/`[move]`/`[delete]`/
`[shell]`/`[archive]` on marked entries, `[copied]`/`[moved]` on lines added by
`p`, and `[new]` on lines you typed (files or directories that `:w` will
create). A line that merely repeats an existing entry’s name is not `[new]`
— that is what a re-rendered listing looks like, and `:w` will refuse it
(claimed twice), not create over it. They update live as you edit; set any
entry in `indicators` to `false` to hide it.


KEYS                                          *gliter.netrw-gliter.netrw-keys*

Every key the plugin binds comes from this table; set one to `false` to disable
it. The multi-key sequences are built from the same table — `%<mark>` is
`regex_prefix` plus the mark key, `*<family>` is `star_prefix` plus a family
key, `*<mark><family>` has the mark key in between — so they follow whatever
you change here:

>
    require('gliter.netrw').setup({
      keys = {
        -- marks
        yank = 'y',          -- toggle a copy mark
        move = 'm',          -- toggle a move mark
        delete = 'd',        -- toggle a delete mark
        archive = 'z',       -- toggle an archive mark
        yank_all = 'Y',      -- copy mark on every entry
        move_all = 'M',      -- move mark on every entry
        delete_all = 'gD',   -- delete mark on every entry
        archive_all = 'Z',   -- archive mark on every entry
        paste = 'p',         -- apply the marks
        clear = '<Esc>',     -- clear all marks
        -- commands
        copy_to = 'C',       -- copy marked to a typed directory
        rename_to = 'R',     -- move/rename marked
        delete_now = 'D',    -- delete marked after confirmation
        execute = 'X',       -- toggle the executable bit (Visual mode:
                             -- on the selection)
        symlink = 'S',       -- symlink marked into a directory
        shell = '!',         -- run a shell command on the marks
        run_each = 'x',      -- shell command one entry at a time;
                             -- %x / *x mark entries for it
        mkdir = '+',         -- create a file, or a directory ending in /
        cd = '<C-g>',        -- :cd to the listed directory
        -- bookmarks
        bookmark = '<C-b>',  -- <C-b>1..9 bookmark this directory;
                             -- <C-b>0 clears all; <C-b>l lists them
        bookmark_jump = { '<C-1>', '<C-2>', '<C-3>', '<C-4>', '<C-5>',
                          '<C-6>', '<C-7>', '<C-8>', '<C-9>' },
                             -- jump to bookmark 1..9 (an unset slot is
                             -- pointed here first)
        -- bulk marking
        regex_prefix = '%',  -- %y %m %d %z %! %x mark by regexp
                             -- (%x = the one-at-a-time run)
        star_prefix = '*',   -- *. */ *@ ** (and *<mark><family>,
                             -- run_each's x included: *x.)
        star_ext = '.',      --   family: by extension
        star_dirs = '/',     --   family: directories
        star_links = '@',    --   family: symlinks
        star_exec = '*',     --   family: executables
        -- edit mode
        edit = 'E',          -- toggle in-place editing of the listing
        edit_cancel = 'q',   -- cancel the edit, discard (apply is always :w)
        -- other
        preview = '<C-p>',   -- where netrw's own preview goes when `paste` is `p`
      },
    })
<

`yank` and `move` are not operators in netrw buffers (`y{motion}` and `yy` do
not exist there). In edit mode, apply is always `:w` and cancel is
`edit_cancel`.

The `<C-1>`..`<C-9>` jump keys need a terminal that sends them — most do;
some reserve a few for tab switching. Every key here is remappable, and a slot
can be switched off by setting its entry in `bookmark_jump` to `false`.


OTHER OPTIONS                        *gliter.netrw-gliter.netrw-other-options*

>
    require('gliter.netrw').setup({
      star_kind = 'copy',  -- 'copy' | 'move' | 'delete' | 'archive' |
                           -- 'shell' | 'run': kind the plain `*` family
                           -- marks with, until a `*<mark><family>` press
                           -- changes it
      conflict = 'ask',    -- 'ask' | 'overwrite' | 'skip' | 'rename' on paste
      indicators = {       -- the [tag] next to marked lines; false hides one
        copy = '  [copy]',
        move = '  [move]',
        delete = '  [delete]',
        shell = '  [shell]',
        archive = '  [archive]',
        run = '  [run]',
        copied = '  [copied]',
        moved = '  [moved]',
        new = '  [new]',
      },
      edit = { confirm = true },  -- ask before applying edits with :w
      notify_level = vim.log.levels.INFO,
    })
<

`native_unmap` lists netrw’s own buffer-local keys that gliter.netrw removes
inside netrw buffers (default `{ 'gR', '+', '%' }`). Set it to `{}` to keep
netrw’s originals.

COMMANDS                                  *gliter.netrw-gliter.netrw-commands*

`:GliterNetrwPaste` applies the marks into the current netrw directory,
`:GliterNetrwClear` clears them, `:GliterNetrwEdit` toggles in-place editing
— the same as `p`, `<Esc>` and `E`. `:GliterNetrwBookmarks` lists the nine
bookmarks.
