1. gliter.readme                                 *gliter.readme-gliter.readme*

The project’s **readme**, opened or created by one key — and the list of
every readme you ever touched, most recent first (Neovim 0.9+).

Emacs’ `recentf` has kept a list of the files you visited, most recent first,
for twenty years. gliter.readme applies the idea to readmes:

- **<Leader>rr** (`:GliterReadme`) — the project’s readme: opened when it
    exists, **created** when it does not (a one-line skeleton — the project’s
    name as a heading), straight in the project’s root. The file’s name is an
    option: `README.md` by default, `README`, `Readme.org`, `NOTES.md` — whatever
    your projects use.
- **<Leader>rl** (`:GliterReadmes`) — every readme you have touched, most
    recent first, in a floating window:
      Key                Does
      ------------------ -------------------------------------------------------
<CR>               open it
<C-t>              open it in a new tab
<C-w>              open it in a horizontal split
<C-v>              open it in a vertical split
      d                  forget it — the list only; the file stays where it is
      j / k, gg / G, /   walk the list (it is a plain buffer)
      q                  close
    Opening a readme again moves it back to the top of the list, the recentf
    behavior.

The list lives in `stdpath('data')/gliter/readmes.json`, capped at
`max_entries` (the oldest fall off).


OPTIONS                                  *gliter.readme-gliter.readme-options*

>lua
    require('gliter.readme').setup {
      file_name = 'README.md',    -- the readme's name in any project dir
      keys = {
        open = '<Leader>rr',      -- the project readme, opened or created
        list = '<Leader>rl',      -- every readme you touched, most recent
                                  -- first
      },
      root_markers = { '.git' },  -- what makes a directory the project's
                                  -- root (the cwd otherwise)
      max_entries = 50,           -- the remembered list's size cap
    }
<

Set a key to `false` to keep it unmapped. The project root is found by walking
up from the current buffer (or the cwd) until a root marker shows up — so the
same key works in every project you edit, and each one gets its own readme
tracked.
