1. gliter.zoom                                       *gliter.zoom-gliter.zoom*

Text-scale for the terminal, **per buffer/window** — and it ships two engines
(Neovim 0.9+):

1. **The style zoom**: `<Leader>=` zooms the current **window/buffer**
in, `<Leader>-` out, `<Leader>0` off — the lines redrawn in the
Unicode "Mathematical Alphanumeric Symbols", the fancy-font-site
alphabet (𝐁𝐨𝐥𝐝, 𝙼𝚘𝚗𝚘𝚜𝚙𝚊𝚌𝚎, Sᴍᴀʟʟ Cᴀᴘꜱ, 🅱🅻🅾🅲🅺🆂, …).
2. **The glyph zoom**: `<Leader>z` toggles — the lines redrawn with a
5x6 SUB-PIXEL bitmap font spelled in the braille dot characters
by default (five drawing rows plus a blank sixth one — the line
gap — so every letter keeps its bottom strokes and its breathing
room), real letters in any terminal, drawn THIN — one dot-column
per stroke, the `|` look. Every scale grows each font pixel to
s×s sub-pixels — the **shape is kept at every scale**, so the
letters resize uniformly and never stretch, and the first size is
small: 3 columns by 3 rows per letter. The
**cursor line is transformed like every other line**, and the
**cursor itself is drawn big** — the letter under it painted in
the cursor’s colors across all of its rows, so `h`/`l` always
show which letter you are on. The **Visual selection paints big too** — charwise, linewise, blockwise, following the selection
as it extends — and so does **every built-in multicursor**
(Neovim 0.13), each in its own colors. The size keys follow the
engine:
**while the glyph zoom is on, <Leader>= / <Leader>- grow / shrink the glyphs** (past the
smallest size they turn it off); with it off they work the style
ladder.

Every other window and buffer on screen keeps its normal size. The two engines
are mutually exclusive per buffer — turning one on turns the other off.


THE STYLE ZOOM                        *gliter.zoom-gliter.zoom-the-style-zoom*

Emacs’ `text-scale-adjust` (`C-x C-+`, `C-x C--`, `C-x C-0`) grows one
buffer’s font because a GUI Emacs draws every face itself. A terminal draws
its whole grid with one font, and every way of changing that font from inside a
program reaches further than the one nvim window you meant: an OS window, a
pane, the whole terminal. None of them is _this window and nothing else_ —
which was the entire point.

So the style zoom zooms the only way that stays inside the buffer: it redraws
the current buffer’s lines **character by character in the Unicode
“Mathematical Alphanumeric Symbols”** (U+1D400–U+1D7FF) and their cousins
— the same alphabet the fancy-font sites use, where every letter and digit
has a bold, italic, script, fraktur, double-struck, sans-serif, monospace or
small-caps twin.


THE LADDER: TWO TABLES, ONE PER DIRECTION ~

There are no level indexes to keep in sync. `styles.zoom_in` and
`styles.zoom_out` are plain lists — the first entry of `zoom_in` is level 1,
the second is level 2; the first entry of `zoom_out` is level -1. **Add, remove
or reorder entries freely**: the number of entries IS the number of levels.

>lua
    require('gliter.zoom').setup {
      styles = {
        zoom_in  = { 'bold', 'underlined', 'mono', 'fullwidth' },
        zoom_out = { 'smallcaps', 'superscript' },
      },
    }
<

With that setup `<Leader>=` goes 𝗕̲𝗼̲𝗹̲𝗱̲ →
𝗨̲𝗻̲𝗱̲𝗲̲𝗿̲𝗹̲𝗶̲𝗻̲𝗲̲𝗱̲ →
𝙼𝚘𝚗𝚘𝚜𝚙𝚊𝚌𝚎 → Ｆｕｌｌｗｉｄｔｈ and
`<Leader>-` comes back through Sᴍᴀʟʟ Cᴀᴩꜱ and
ˢᵘᵖᵉʳˢᶜʳⁱᵖᵗ. The defaults are every style that ships, in the
order of the options block at the end of this page — trim the ladders to
taste.

`:GliterZoomStyles` prints **every style with a live example** (the word under
the cursor, or `Example`) — the whole menu, in nvim.

HOW IT DRAWS ~

- The buffer’s lines are never touched — each rendered line gets one
    **overlay extmark** (virtual text at column 0) carrying the styled
    text, so edits, undo and the file on disk are exactly what they were.
- The overlay uses `hl_mode "combine"`: the buffer’s own treesitter /
    `:syntax` colors shine **through** the styled glyphs, and the bold
    levels add the terminal’s ANSI bold on top of them. (Set
    `hl_mode = 'replace'` for flat single-color zooming.)
- The styled glyphs stay one cell wide (`fullwidth` and `squared` are
    the two-cells-per-char exceptions), so the cursor and its column
    keep their place and you keep typing on the line you are editing.
- `'wrap'` is forced off while a buffer is zoomed (an overlay cannot
    wrap) and restored exactly when the zoom ends. Tabs expand to the
    tabstop so the overlay covers the same cells the real line covers.
- The overlay follows edits, scrolling and window resizes; a
    colorscheme cannot kill it (the style groups are redefined); wiping
    the buffer clears its level.
- If nui.nvim <https://github.com/MunifTanjim/nui.nvim> is installed,
    every zoomed line is composed as a **NuiText component**
    (`require('nui.text')`) — the same primitive noice and the nui
    popups render with. Without it the overlay is built from plain
    `virt_text` tuples; both paths render the identical extmark. Set
    `nui = false` to always take the plain path, `true` to be told when
    nui.nvim is missing.


THE GLYPH ZOOM                        *gliter.zoom-gliter.zoom-the-glyph-zoom*

`<Leader>z` toggles the second engine: every line of the buffer — **the
cursor line included** — is redrawn with a 5x6 SUB-PIXEL bitmap font spelled
in the braille dot characters by default (the solid half-blocks and the shades
are a `glyph.quads` away). Real letters, any terminal, over ssh, inside tmux,
still the buffer’s own colors — and **thin**: one dot-column per stroke,
the `|` look.

- **Thin, like |**: the font is drawn on the SUB-PIXEL grid —
    one bitmap pixel is half a cell wide and half a cell tall, and the
    default quads spell it in braille dots, so every stroke is a single
    dot-column and `I` is literally a dotted `|`. A letter is **3 columns + its gap by 3 rows** at x1 — five font rows of letter plus
    the blank sixth row, the line gap.
- **No stretching — shape kept at every scale**: at scale
    `s` every bitmap pixel grows to `s x s` sub-pixels — the SAME shape,
    thin strokes included, at every size, so the letters resize
    uniformly and never stretch.
- **The size ladder**: plain `<Leader>z` (or `1<Leader>z`) turns on at
    **x1, the small size** — 3 columns by 3 rows a line (2½ rows of
    letter, the rest the gap). `2<Leader>z` is **6x6**, `3<Leader>z` is
    **9x9**, `4<Leader>z` is **12x12**, up to `glyph.max_scale` (4 by
    default) — every step the same letters, uniformly bigger, just as
    thin, the line gap included. Pressing `<Leader>z`
    with the same count again turns it off; plain `<Leader>z` toggles
    off↔the last size. `:GliterZoomGlyph 3` does the same from the
    command line.
- **The size keys follow the engine**: while the glyph zoom is
    on, `<Leader>=` grows it one scale and `<Leader>-` shrinks it one
    scale — and shrinking past x1 turns the glyphs off. A count steps
    that many scales
    (`2<Leader>=`). Once the glyphs are off the keys are the style
    ladder again. `<Leader>0` always resets both engines.
- **The cursor line** is transformed like every other line (that is
    the point — the zoomed view is uniform), and the **cursor is drawn big**: the letter under the cursor is painted in the cursor’s
    colors (`GliterZoomCursor`, linked to `Cursor`) across all of its
    rows — one zoomed-letter-sized cursor. Why: the terminal’s own
    cursor is one cell and the real text’s grid is one cell per
    character, so `h`/`l` move it a cell at a time while every letter
    is three cells wide at x1 — the big painted letter is what shows
    which one you are on. It follows every motion (`CursorMoved`
    re-renders); set `glyph.cursor = false` for the plain small one.
    The paint never bleeds sideways: a cursor standing on a run of
    spaces covers exactly its own letter — the spaces after it keep
    the color of the token before the cursor, not the cursor’s. Some
    terminals draw the cursor under overlay extmarks; if yours
    does, set `glyph.skip_cursor_line = true` instead and the cursor
    line stays real text at the same height.
- **Visual and multicursors paint big too**: the Visual selection is
    spelled into the glyphs (`GliterZoomVisual` → `Visual`) —
    charwise, linewise and blockwise, following the selection as it
    extends — and every built-in multicursor (Neovim 0.13: the
    extmarks in the `nvim.multicursor` namespace) gets the same
    big-letter cursor in its own colors (`GliterZoomMCursor` →
    `MCursor`, falling back to `Cursor` before 0.13). Both follow the
    `glyph.cursor` switch; the multicursor commands that place or
    remove a cursor without moving yours (`Q`, `q=`, `zq`, …)
    re-render through `CmdAtom`, the built-in’s plugin hook, and the
    rest where the keys settle.
- **Per buffer, per window**: the level belongs to the buffer; every
    window showing it gets its own viewport rendered (margin lines above
    and below, so scrolling does not flash). Empty lines keep their
    one-row height — separators do not grow with the text.
- **Colors**: treesitter highlights when a parser is around, `:syntax`
    when it is not, `glyph.hl_group` (`Normal`) for cells with no group
    of their own. The half-block cells are drawn `hl_mode "replace"` —
    the glyphs must fully own their cells.
- **The font**: A–Z, 0–9 and the common punctuation are built in as
    5x6 sub-pixel bitmaps (rows separated by `/`, 1 = pixel on, one
    bitmap pixel = half a cell wide and half a cell tall; the five
    drawing rows are the letter, the blank sixth one the line gap);
    unknown characters draw as O. `glyph.font` merges your own bitmaps
    over the built-ins — redraw a letter
    (`font = { A = '01110/10001/11111/10001/10001/00000' }`), add one
    the font lacks
    (`font = { ['→'] = '00010/00100/01110/00100/00000/00000' }`), or
    spell a whole font of your own (wider or taller bitmaps work; every
    glyph is padded to the widest one’s width, the letter gap is one
    font pixel and the line gap the last blank font row). The 16
    sub-pixel characters live in `glyph.quads`, indexed by bitmask
    (TL_8 + TR_4 + BL_2 + BR_1) — **braille dots by default**, the
    lightest and most readable spelling; swap in the solid half-blocks
    for denser letters, or the shades for something in between.
- Turning the glyph zoom on turns the style zoom off, and the other
    way around — one engine at a time per buffer.


OPTIONS                                      *gliter.zoom-gliter.zoom-options*

>lua
    require('gliter.zoom').setup {
      keys = {
        increase = '<Leader>=',  -- grow: the glyph scale while the glyph zoom
                                 -- is on, the style level otherwise
        decrease = '<Leader>-',  -- shrink: the glyph scale while the glyph zoom
                                 -- is on (past x1: off), the style level otherwise
        reset    = '<Leader>0',  -- both engines: off
        glyph    = '<Leader>z',  -- glyph zoom: toggle (a count sets the scale)
      },
      echo = true,               -- say the state on every change
      styles = {
        -- every font that ships, in one ladder each — trim to taste:
        zoom_in  = { 'bold', 'italic', 'bold_italic', 'script', 'bold_script',
                     'fraktur', 'bold_fraktur', 'double_struck', 'sans',
                     'sans_bold', 'sans_italic', 'sans_bold_italic', 'mono',
                     'underlined', 'circled', 'squared', 'fullwidth' },
        zoom_out = { 'smallcaps', 'superscript' },
      },
      margin = 20,               -- lines drawn above/below the window
      nui = 'auto',              -- 'auto' | true | false: NuiText components
      hl_mode = 'combine',       -- 'combine' keeps colors; 'replace' flats
      glyph = {
        max_scale = 4,           -- deepest glyph scale (1 = the small thin
                                 -- size, 2 = 6x6, 3 = 9x9, 4 = 12x12)
        hl_group = 'Normal',     -- the color of unhighlighted glyph cells
        skip_cursor_line = false,-- true keeps the cursor line real text
        cursor = true,           -- draw the cursor big: the letter under
                                 -- the cursor painted in the cursor's
                                 -- colors across all of its rows; false =
                                 -- the terminal's plain 1-cell cursor.
                                 -- The Visual selection and every
                                 -- multicursor paint the same way
        font = {},               -- your own 5x6 sub-pixel bitmaps over the
                                 -- built-ins
        -- the 16 sub-pixel characters by bitmask; braille dots by
        -- default, the half-blocks denser, the shades in between:
        --   quads = { ' ', '▗', '▖', '▄', '▝', '▐', '▞', '▟', '▘', '▚', '▌', '▙', '▀', '▜', '▛', '█' },
        quads = { '⠀', '⢠', '⡄', '⣤', '⠘', '⢸', '⡜', '⣼',
                  '⠃', '⢣', '⡇', '⣧', '⠛', '⢻', '⡟', '⣿' },
        --   quads = { ' ', '░', '░', '▒', '░', '▒', '▒', '▓', '░', '▒', '▒', '▓', '▒', '▓', '▓', '█' },
      },
    }
<

Set any key to `false` to keep it unmapped. The module exports
`increase(count?)`, `decrease(count?)`, `reset()`, `level()` (0 = off, negative
= smaller), `set_level(n)`, `glyph_level()`, `glyph_set(scale)` (0 = off, 1 =
the small size), `glyph_toggle(count)` and `statusline()` (`Z2` at style level
2, `G3` at glyph scale 3). `:GliterZoomSet -1`, `:GliterZoomGlyph 3`,
`:GliterZoomState` and `:GliterZoomStyles` work from the command line.


NOTES                                          *gliter.zoom-gliter.zoom-notes*

- Whether the styled glyphs look bigger, bolder or just different
    depends on the font your terminal falls back to for U+1D400 — try a
    font with good mathematical coverage for the best effect. They are
    one cell wide to Neovim either way, so columns never shift
    (`fullwidth` and `squared` excepted — those two are the wide ones).
- `conceal`ed text is revealed by an overlay (the styled text does not
    conceal); folds still show their fold line.
- Two buffers can hold two different zooms at once — the scratch
    buffer in glyphs, the file next to it in bold, a third one normal.
