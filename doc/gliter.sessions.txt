1. gliter.sessions                           *gliter.sessions-gliter.sessions*

`:mksession` **with a memory** (Neovim 0.9+).

Emacs has remembered whole desktops since the nineties: `M-x desktop-save`
wrote one down, `M-x desktop-read` brought it back. Neovim’s `:mksession`
writes a perfectly good session file — and then forgets it exists.
gliter.sessions gives it the memory:

- **<Leader>ss** (`:GliterSessionSave [name]`) — `mksession!` into the
    **project’s root**, the directory you were editing, exactly where a plain
    `:mksession` would put it — `Session.vim` by default, `<name>.vim` for a
    named one — and the session is **remembered**: its name, its file, its
    directory, and when. Saving again under the same name **updates** that session
    in place.
- **<Leader>sl** (`:GliterSessions`) — every session gliter knows about, most
    recently used first, in a floating window:
      -----------------------------------------------------------------------
      Key                              Does
      -------------------------------- --------------------------------------
<CR>                             activate it — :source the session
                                       file; its own cd, windows, buffers and
                                       folds come with it
      d                                delete it — asks first, then drops the
                                       registry entry and the session file
      j / k, gg / G, /                 walk the list (it is a plain buffer)
      q                                close
      -----------------------------------------------------------------------
    A `*` marks the sessions of the directory you are in; a `(file missing)` marks
    the ones whose file was removed underneath them.
- **:GliterSessionLoad [name]** — activate without the window; no argument
    loads the most recently used one. A name picks the session of that name **in
    the current directory** first, then anywhere.
- **:GliterSessionDelete [name]** — delete without the window (it asks first,
    too).

The session files are plain `:mksession` output — `:source Session.vim` works
with or without gliter, forever. The registry lives in
`stdpath('data')/gliter/sessions.json`, capped at `max_entries` (the oldest
fall off).


OPTIONS                              *gliter.sessions-gliter.sessions-options*

>lua
    require('gliter.sessions').setup {
      file_name = 'Session.vim',  -- the session file's name inside the
                                  -- project root
      keys = {
        save = '<Leader>ss',      -- mksession! into the project + remember
        list = '<Leader>sl',      -- every known session, in a float
      },
      root_markers = { '.git' },  -- what makes a directory the project's
                                  -- root (the cwd otherwise)
      max_entries = 100,          -- the registry's size cap
    }
<

Set a key to `false` to keep it unmapped. The project root is found by walking
up from the current buffer (or the cwd) until a root marker shows up.


NOTES                                  *gliter.sessions-gliter.sessions-notes*

- 'sessionoptions' is left exactly as you have it — the session file
    records what your own Neovim would record.
- Activating a session sources it over the current state, the way
    `:source` does; gliter closes its own float first so nothing fights
    the restore.
- A named session and the default one are separate entries when both
    are saved (`Session.vim` and `work.vim` in the same project).
