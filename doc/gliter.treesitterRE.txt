1. gliter.treesitterRE               *gliter.treesitterRE-gliter.treesitterre*

Treesitter- and word-based selection expansion for Neovim, built around the
nvim-expand-region <https://github.com/lth-go/nvim-expand-region> model: press
one key and the visual selection climbs a ladder of increasingly large regions
— word → key/value pair → the inside of the brackets (trimmed, then raw)
→ the bracket pair itself → the enclosing statement — and another key
walks the same ladder back down. The RE stands for region-expand.

Every action also works in buffers **without** a treesitter parser (no
filetype, no parser installed): the ladder then runs word → bracket pairs →
line → paragraph, and the sibling/scope keys operate on words and paragraphs
instead.


STOLEN FROM EMACS  *gliter.treesitterRE-gliter.treesitterre-stolen-from-emacs*

The one-key growing selection is expand-region
<https://github.com/magnars/expand-region.el>: `C-=` in Emacs grows the region
by semantic units — word, symbol, string, defun — and a negative prefix
argument walks it back down. magnars shipped it in 2011, fourteen years before
anyone built a treesitter ladder on this side. gliter.treesitterRE keeps the
model (and the rule that the outermost statement, never the whole buffer, is
the top rung) and rebuilds the rungs out of treesitter nodes plus a plain text
scan of the bracket pairs, so the climb also works inside comments and in
parser-less buffers. The ladder order follows nvim-expand-region
<https://github.com/lth-go/nvim-expand-region> (2025), which made this same
trip from Emacs first. If you have used expand-region, your hands already know
everything on this page.


INSTALL                      *gliter.treesitterRE-gliter.treesitterre-install*

`gliter.treesitterRE` is a module of gliter (one repository, one runtime path):

>lua
    -- lazy.nvim
    {
      'you/gliter',
      opts = {
        treesitterRE = {},   -- defaults below; rebind through `keys`
      },
    }
<

Modules are opt-in: naming `treesitterRE` in `setup()` — or calling
`require('gliter.treesitterRE').setup()` yourself — gives the module its
default keys; leaving it out loads nothing at all. Rebind through the `keys`
table — set one to `false` to disable it — or set `keys = false` to create
no default keys at all and map the `<Plug>` mappings yourself:

>lua
    require('gliter').setup { treesitterRE = { keys = false } }
    vim.keymap.set({ 'n', 'x' }, '+', '<Plug>(TreesitterREUp)')
<


KEYS                            *gliter.treesitterRE-gliter.treesitterre-keys*

  ------------------------------------------------------------------------------
  Key      Action         What it does
  -------- -------------- ------------------------------------------------------
  <BS>     expand_up      nvim-expand-region ladder — climb one rung per press
                          (see below)

  <M-BS>   expand_down    undo / shrink — walk the ladder back down; on a manual
                          selection, descend one structural level inward; at the
                          very bottom, leave Visual mode

  <M-n>    expand         cycle same-level nodes — the flat sequence of nodes at
                          the current tree depth: siblings and the neighbors’
                          tokens, wrapping around (see below)

  <M-p>    contract       the same cycle, backwards

  <M-f>    expand_right   grow the selection one word to the right (like e/w
                          chaining)

  <M-b>    expand_left    grow the selection one word to the left (like b)

  <M-u>    left_out       push the left edge out by one character (the v_h
                          equivalent for the left side)

  <M-o>    left_in        pull the left edge in by one character (the v_l
                          equivalent), keeping at least one character

  <M-w>    hop_word       viw at the edge of the last lateral motion — the right
                          edge after <M-f> (where the cursor sits), the left
                          edge after <M-b> (where a native vb would have put
                          it). Narrows to / completes the edge word; when the
                          edge word already is the whole selection, hops to the
                          next word in that direction

  gl / gh  next_sibling / slide to the next/previous sibling; climbs a level
           prev_sibling   when the sibling chain is exhausted

  gj / gk  next_scope /   hop to the next/previous function / if / loop / …
           prev_scope     (paragraph, without a parser)
  ------------------------------------------------------------------------------
All keys are mapped in both Normal and Visual mode. From Normal mode each
action first grips the word (or node) under the cursor. Set any key to `false`
in `setup()` to disable it.


THE <BS> LADDER      *gliter.treesitterRE-gliter.treesitterre-the-<bs>-ladder*

Around the current selection the module collects every enclosing region it can
find, sorts them by size (exactly like nvim-expand-region) and walks that list
one rung per press:

- the completed word, when the selection covers part of one
- enclosing bracket pairs found by a **text scan** — each pair offers three
    rungs: the inside with the padding trimmed off, the raw inside, and the
    pair with its delimiters. The text scan works inside comments and in
    parser-less buffers.
- treesitter ancestors, each optionally contributing the span between its
    delimiters (and the trimmed span) as separate rungs
- the trimmed line, the full line
- the paragraph (only without a treesitter parser)

For

>lua
    local config = {
      highlight = { enable = true, use_languagetree = true },
    }
<

with the cursor inside the second `true`, `<BS>` walks:

>lua
    -- highlight = { enable = true, [use_languagetree = true] },   -- the pair
    -- highlight = { [enable = true, use_languagetree = true] },   -- inside the braces, trimmed
    -- highlight = {[ enable = true, use_languagetree = true ]},   -- inside the braces, raw
    -- highlight = [{ enable = true, use_languagetree = true }],   -- with the braces
    -- [highlight = { enable = true, use_languagetree = true }],   -- the whole field
    -- … line, enclosing table, `local config = …` — and stops there
<

The **tree root and the whole document are never rungs**: with a parser the
ladder stops at the outermost statement; without one, at the paragraph.
`<M-BS>` walks the same rungs back down, one per press.


<M-BS> (SHRINK) DETAILS *gliter.treesitterRE-gliter.treesitterre-<m-bs>-(shrink)-details*

- after any treesitterRE operation it **undoes the last change** — ladder
    steps, word extensions (`<M-f>`/`<M-b>`/`<M-u>`/`<M-o>`), word hops and
    sibling moves alike
- on a selection that did not come from the module (your own manual
    selection) it **descends structurally**: `foo("bar")` → `"bar"` → `bar`;
    repeated presses keep descending and never ping-pong between two levels
- when the history is exhausted it leaves Visual mode


<M-N>/<M-P> VS GL/GH *gliter.treesitterRE-gliter.treesitterre-<m-n>/<m-p>-vs-gl/gh*

`<M-n>`/`<M-p>` cycle through the **flat sequence of nodes at the current tree
depth** — not just the siblings of the current node, but the nodes continuing
in the neighboring subtrees, wrapping around at the ends. In

>lua
    highlight = { enable = true, use_languagetree = true }
<

starting from the key `enable`, `<M-n>` walks the tokens of the whole table:

>lua
    highlight = { [enable] = [true], [use_languagetree] = [true] }
                        -- enable -> true -> use_languagetree -> true -> (wrap)
<

At the field level (selection = `enable = true`) the same keys walk the fields,
at the statement level the statements. The move always replaces the selection
— it never grows.

`gl`/`gh` instead move to the next/previous **sibling** of the current node and
climb a level when that chain runs out — from the last token of `enable =
true`, `gl` lands on the next whole field `use_languagetree = true`.


<M-W> (WORD GRAB)  *gliter.treesitterRE-gliter.treesitterre-<m-w>-(word-grab)*

`<M-w>` is `viw` at the edge where the last lateral motion happened: the
**right** edge after `<M-f>` (the cursor really sits there) and the **left**
edge after `<M-b>` (where a native `vb` would have left it, even though the
cursor never moved).

- the edge char is inside a word → that whole word is selected — a
    partially covered edge word is completed, a multi-word selection is
    narrowed to its edge word
- that word already is the whole selection → hop to the next word in
    the direction (like `viw` after `w`/`b`)
- the edge sits on blanks → the next/previous word in the direction

So a selection ending in `},` grabs the local `},` — it never jumps to the
next line for punctuation.


<M-U>/<M-O> (LEFT EDGE, CHARACTER-WISE) *gliter.treesitterRE-gliter.treesitterre-<m-u>/<m-o>-(left-edge,-character-wise)*

The `v_l`/`v_h` equivalent for the **left** side of the selection, one
**character** at a time: `<M-u>` extends the left edge left (staying on the
line, like `h`), `<M-o>` retracts it right (like `l`, keeping at least one
character). The word-wise left growth lives on `<M-b>`.


CONFIGURATION          *gliter.treesitterRE-gliter.treesitterre-configuration*

>lua
    require('gliter').setup({
      treesitterRE = {
        keys = {
          expand       = '<M-n>',
          contract     = '<M-p>',
          expand_right = '<M-f>',
          expand_left  = '<M-b>',
          expand_up    = '<BS>',
          expand_down  = '<M-BS>',
          left_out     = '<M-u>',
          left_in      = '<M-o>',
          hop_word     = '<M-w>',
          next_sibling = 'gl',
          prev_sibling = 'gh',
          next_scope   = 'gj',
          prev_scope   = 'gk',
        },
      },
    })
<

The module can be set up directly too —
`require('gliter.treesitterRE').setup({ keys = { ... } })` — and gliter keeps
that configuration: it only sets up the modules you name in its own `setup()`.

`<Plug>` mappings are available too: `<Plug>(TreesitterREUp)`,
`<Plug>(TreesitterREShrink)`, `<Plug>(TreesitterRERight)`,
`<Plug>(TreesitterRELeft)`, `<Plug>(TreesitterRELeftOut)`,
`<Plug>(TreesitterRELeftIn)`, `<Plug>(TreesitterREHopWord)`,
`<Plug>(TreesitterREExpand)` (next sibling), `<Plug>(TreesitterREContract)`
(previous sibling), `<Plug>(TreesitterRENextSibling)`,
`<Plug>(TreesitterREPrevSibling)`, `<Plug>(TreesitterRENextScope)`,
`<Plug>(TreesitterREPrevScope)`.


TERMINAL NOTE          *gliter.treesitterRE-gliter.treesitterre-terminal-note*

`<M-BS>` requires the terminal to deliver Alt+Backspace as ESC+DEL (`0x1b
0x7f`). kitty, WezTerm, alacritty and iTerm2 do this by default; inside tmux
also `set -sg escape-time 10`. If yours cannot, rebind `expand_down` to
something else.
