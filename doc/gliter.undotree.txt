1. gliter.undotree                           *gliter.undotree-gliter.undotree*

Extra features for the built-in `:Undotree` viewer (the `nvim.undotree` dist
plugin, Neovim 0.12+): loads the viewer for you and maps `<Leader>u` to open
the tree and close it again from any of its windows, colors every part of the
tree panel (branch glyphs, node markers, sequence numbers, time stamps, the
current state) and shows the diff of each undo step in **one window at the
bottom of the screen, full width**.


STOLEN FROM EMACS          *gliter.undotree-gliter.undotree-stolen-from-emacs*

The tree gliter.undotree repaints got to Neovim the long way: Toby Cubitt’s
undo-tree <https://gitlab.com/tarsius/undo-tree> drew the branching history in
Emacs in 2009; mbbill/undotree <https://github.com/mbbill/undotree> (2012) —
the undo history visualizer for Vim — redrew it on this side; and Neovim 0.12
ships a descendant of mbbill’s viewer as the `nvim.undotree` dist plugin
behind `:Undotree`, which is the tree this module colors. The palette below —
UndotreeBranch, UndotreeNode, UndotreeSeq, UndotreeSavedSmall… — is
undo-tree’s face set, name for name: the Emacs package was there first, three
years before the Vim port and well over a decade before the built-in viewer.
What every later version leaves out is the other half of the original: the
diff. gliter.undotree puts it back — one window at the bottom of the screen
that follows the cursor through the states, exactly like undo-tree’s diff
window. If you have used undo-tree, your hands already know everything on this
page.


SETUP                                  *gliter.undotree-gliter.undotree-setup*

>lua
    require('gliter.undotree').setup {
      toggle = '<Leader>u',  -- open the tree, or close it from inside it
      difftool = true,       -- :packadd nvim.difftool — the diff panel's engine
      diff_panel = 'auto',   -- 'auto' | true | false
      panel_height = 10,     -- height of the bottom diff window
    }
<

Or through gliter: `require('gliter').setup { undotree = { panel_height = 6 }
}`.

The module loads the built-in viewer itself (`:packadd nvim.undotree`) — no
line needed in your init.lua. `difftool = true` (the default) also loads
`nvim.difftool`, and `diff_panel = 'auto'` opens the bottom panel whenever
difftool is loaded — with the default that means "together with the tree".
Set `difftool = false` if you load difftool yourself or never want it;
`diff_panel = true` opens the panel unconditionally, `false` never.


THE TOGGLE KEY                *gliter.undotree-gliter.undotree-the-toggle-key*

`<Leader>u` opens the tree, and pressing it again closes it — from the tree
window, from the buffer being edited, and from the diff panel. The last one is
the fix: the built-in `require('undotree').open()` (and `:Undotree`) only close
the tree when the current buffer is the edited buffer or the tree itself, so
pressed in the diff panel — or any other buffer — it opens a _second_ tree
window. gliter’s toggle knows the panel belongs to the tree and closes it
instead (closing the tree takes the panel with it). Set `toggle = false` for no
key, or another key to move it.


WHAT IT DOES                    *gliter.undotree-gliter.undotree-what-it-does*

- `<Leader>u` (the `toggle` option) opens the tree and closes it again
    from any of its windows — see above
- moving through the tree updates the diff window (state you came from →
    state under the cursor)
- `D` in the tree toggles the diff window
- the window opens automatically when `nvim.difftool` is loaded
    (`:packadd nvim.difftool`); set `diff_panel = true` to always open it,
    `false` to never
- `+` / `-` / `@@` lines use the standard diff highlighting (`filetype=diff`);
    changed lines in the edited buffer get `++ / ~~ / --` signs and
    DiffAdd/DiffChange line colors
- the `+N -M` summary bar is shown in the panel statusline

Override any color with `:hi` (defaults are links, shown in brackets):

>
    UndotreeBranch       (Constant)     | \ / connectors
    UndotreeNode         (Question)     * node marker
    UndotreeNodeCurrent  (Statement)    * on the current state's line
    UndotreeSeq          (Comment)      sequence numbers
    UndotreeCurrent      (Statement)    sequence number of the current state
    UndotreeTimeStamp    (Function)     (time stamp)
